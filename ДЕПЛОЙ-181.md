# Деплой 181 — записи домена для SMTP.BZ

## Что случилось

SMTP.BZ при подключении домена просит три записи, и одна из них — SPF —
уже есть в зоне (от Unisender). Добавить её второй раз нельзя: в домене
может быть **только одна** запись SPF. Две записи почтовые сервисы
считают ошибкой настройки и перестают проходить проверку по **всем**
письмам домена, включая те, что уходили раньше.

`tools/check-dns.js` до этого знал только Unisender: селекторы DKIM,
SPF, поддомен обратного адреса. По SMTP.BZ он молчал, а на единственной
SPF-записи с одним сервисом внутри ставил галочку.

## Что сделано

**`tools/check-dns.js` переписан под два сервиса.** Список сервисов
вынесен в `PROVIDERS` наверху файла — добавится третий, правится одно
место. Проверяются:

- SPF: одна ли она, есть ли внутри оба сервиса; при дубле и при
  нехватке печатается **готовая объединённая строка** для вставки;
- DKIM отдельно у каждого — `smtpbz._domainkey` и селекторы Unisender;
- CNAME `stats` → `smtp.bz.` (нужен SMTP.BZ для статистики);
- DMARC, подтверждение владения, поддомен обратного адреса — как раньше.

Итог теперь печатается по каждому сервису отдельно и называет, чего
именно не хватает. Готовность процесса (код выхода) считается по
основному сервису.

**`test/dnsmerge.test.js` (новый, 26 проверок).** Сборка SPF проверяется
вызовом настоящей функции, без похода в DNS: сохраняются ли чужие
механизмы (`a`, `mx`, `ip4:`, сторонние `include`), не задваивается ли
`include` в другом регистре, остаётся ли ровно один `v=spf1` и один
`all`, стоит ли `all` последним, не растёт ли число DNS-запросов выше
предела в 10, и не портит ли повторный прогон уже собранную строку.

Файл теперь экспортирует `mergedSpf` и `PROVIDERS`, а проверку запускает
только при прямом вызове (`require.main === module`).

**`ПОЧТА-И-ДОМЕН.md`** — таблица записей SMTP.BZ с именами в том виде,
в каком их принимает Selectel (для `@` имя пустое, поддомены без
`.aliance-general.ru`), раздел про SPF с готовой строкой и напоминание
включить в карточке домена переключатель **«Транзакции»**.

## Что делать владельцу

1. В Selectel **исправить** существующую TXT-запись SPF на:
   ```
   v=spf1 a mx include:spf.smtp.bz include:spf.unisender.ru ~all
   ```
   Именно исправить, не добавить рядом.
2. Добавить TXT `smtpbz._domainkey` со значением из кабинета SMTP.BZ.
3. Добавить CNAME `stats` → `smtp.bz.`
4. Через 15–30 минут: `node tools/check-dns.js aliance-general.ru`
5. Когда всё зелёное — «Проверить» в кабинете SMTP.BZ, включить
   «Транзакции», забрать ключ API в `SMTPBZ_API_KEY`.
