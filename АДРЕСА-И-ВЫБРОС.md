# Адреса игроков и выброс из кабинета

Две вещи в одном месте: почему у всех один адрес и как это чинится, и как
заставить игроков войти заново.

---

## Часть 1. Почему у всех 127.0.0.1

Игра стоит **за nginx**. Игрок стучится в nginx, а nginx уже — в игру.
Значит, соединение к игре приходит **от nginx**, и сервер честно видит
адрес того, кто к нему подключился: самого себя, `127.0.0.1`.

Настоящий адрес игрока знает только nginx. Передать его дальше он обязан
отдельным заголовком — сам по себе адрес не путешествует. Если заголовка
нет, адрес **теряется навсегда**: восстановить его потом неоткуда.

Подлость в том, что игра при этом работает нормально. Тихо ломаются
только журнал входов, поиск мультоводов и блокировка по адресу — а
внешне всё в порядке.

### Шаг 1. Найти, где чинить (30 секунд)

```bash
cd ~/Aliance-Generals
bash tools/check-proxy.sh
```

Скрипт **ничего не меняет**. Он находит боевые конфиги nginx, считает в
них блоки `proxy_pass` на порт игры и говорит, в каких не хватает
заголовков:

```
3. Передаётся ли адрес игрока
  /etc/nginx/sites-enabled/generals
    блоков proxy_pass: 2 · X-Real-IP: 0 · X-Forwarded-For: 0
    ⛔ заголовков не хватает — адрес игрока сюда не доходит
```

Если скрипт скажет, что `proxy_pass` на порт игры не найден вообще —
значит проксирует что-то другое (другой порт, Apache, балансировщик
хостинга, Cloudflare). Настраивать нужно там же.

### Шаг 2. Починить

```bash
sudo nano /etc/nginx/sites-enabled/generals
```

В **каждый** блок `location`, где есть `proxy_pass` на игру, добавить
три строки:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:3000;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Именно в каждый: блоков обычно два (`/api/` и `/`). Добавишь в один —
половина запросов останется без адреса, и картина будет наполовину
верной, что хуже, чем никакой.

Проверить и применить:

```bash
sudo nginx -t && sudo nginx -s reload
```

`nginx -t` обязателен: он ловит опечатку **до** перезапуска. Без него
кривой конфиг положит сайт целиком.

Готовый рабочий пример лежит в проекте — `nginx.example.conf`.

### Шаг 3. Убедиться

**Панель → «Техника» → «Проверки» → «Проверка сети» → «Проверить».**

Должно стать так:

```
Определён адрес        95.24.1.7        ← настоящий адрес
x-real-ip              95.24.1.7
x-forwarded-for        95.24.1.7
Соединение с           127.0.0.1        ← это нормально, это nginx
```

Строка «Соединение с 127.0.0.1» остаётся — так и должно быть.

### Про старые записи

Адрес пишется **в момент входа**. У тех, кто заходил до починки,
останется старая запись, пока они не зайдут снова. Задним числом я эти
записи не переписываю намеренно: откуда люди заходили, мы не знаем, а
выдумывать данные в журнале входов нельзя — по нему потом разбирают
спорные случаи.

Через несколько дней, когда все перезайдут, картина станет полной сама.

### Если после починки адреса всё равно совпадают

Это уже нормальная жизнь, а не поломка:

- за одним домашним роутером сидит семья — общий внешний адрес;
- мобильные операторы выдают один адрес сотням абонентов;
- один человек заходит с работы и из дома.

Совпадение адреса **само по себе ничего не доказывает**. Поэтому в
панели рядом теперь есть сигнал посильнее — совпадение **устройства**
(см. ниже).

## Часть 2. Что нового видно про игрока

**Панель → «Игроки» → карточка → «Входы и устройства».**

| Раздел | Что показывает |
|---|---|
| При регистрации | когда, с какого адреса и устройства создан аккаунт |
| Устройства | все устройства аккаунта: модель, система, браузер, сколько входов, когда впервые и последний раз, **и с каких адресов заходили именно с него** |
| Открытые входы | где кабинет открыт прямо сейчас + кнопки закрыть |
| Журнал безопасности | смена пароля, вход с нового устройства, включение 2FA, выброс из кабинета |
| Адреса | сводка по адресам, как было |
| История входов | последние 20 входов, как было |

У каждого устройства есть кнопка **«Кто ещё с этого устройства»**. Это
сильнее совпадения адреса: за адресом стоит весь дом или целый оператор,
а за устройством — как правило, один человек.

**Как узнаётся устройство.** Строка браузера плюс отпечаток, который
присылает сам браузер: размер экрана, часовой пояс, язык, число ядер.
Без отпечатка половина игроков выглядела одинаково («ПК, Windows 10,
Chrome»), и вопрос «кто ещё сидел за этой машиной» не имел смысла.

Чего это **не** значит: отпечаток не привязан к человеку. Смена браузера
или переустановка системы дают новую запись, а общий компьютер в семье
или в клубе даёт совпадение честно. Это повод посмотреть внимательнее,
а не приговор.

## Часть 3. Выкинуть из кабинета

Зачем: после утечки пароля, смены правил или подозрения на угон нужно,
чтобы человек ввёл пароль заново. Бан для этого не годится — он
наказывает. Здесь наказания нет: игрок вводит пароль и продолжает играть.

### Одного игрока

**Панель → «Игроки» → карточка → «Входы и устройства» → «Открытые входы»:**

- **«Закрыть»** у строки — гасит **одну** сессию. Пример: игрок пишет,
  что забыл выйти на чужом компьютере — закрываешь именно её, телефон
  продолжает работать.
- **«Выкинуть из кабинета совсем»** — гасит все входы этого игрока.

### Всех разом

**Панель → «Открытые входы»** (новый раздел в меню):

- видно, сколько сейчас открытых входов и у кого;
- у каждого игрока — устройство, адрес, когда вошёл, когда последний раз
  что-то делал;
- кнопка **«Выкинуть всех»** закрывает все сессии сервера сразу.

Про «всех»: **твоя собственная сессия тоже закроется** — панель попросит
войти заново. Это не оплошность, а следствие честного действия: «все»
означает все. Панель предупреждает об этом до нажатия.

Каждый выброс попадает и в журнал безопасности игрока, и в общий журнал
действий — видно, кто и когда его сделал.
