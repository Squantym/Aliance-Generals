# ⭐ АЛЬЯНС ГЕНЕРАЛОВ ⭐

Браузерная военная текстовая стратегия. Регистрируйся, строй армию, воюй с другими генералами, развивай базу и становись легендой.

## 🚀 Быстрый запуск (локально, без базы данных)

```bash
npm install
npm run build
node dist/server.js
```

Данные сохраняются в JSON-файлы в папку `/data` — базу поднимать не нужно.
Проект на TypeScript, поэтому перед запуском нужна сборка.

- Игра: `http://localhost:3000/`
- Админ-панель: `http://localhost:3000/admin`

## 🖥 Боевой сервер: своя база (SQLite)

Облачной MongoDB в проекте больше нет. Игра работает на своей базе —
один файл `data/generals.db` на том же сервере, что и процесс.

| Переменная | Значение |
|---|---|
| `DB_DRIVER` | `sqlite` — своя база. Если не задана, но рядом лежит `data/generals.db`, база откроется всё равно |
| `SQLITE_DIR` | папка базы (по умолчанию `./data`) |
| `SQLITE_FILE` | имя файла (по умолчанию `generals.db`) |
| `APP_URL` | публичный адрес игры (для ссылок в письмах) |
| `RESEND_API_KEY` | ключ resend.com (подтверждение почты, необязательно) |
| `EMAIL_FROM` | `Генералы <noreply@твойдомен.com>` |

Запуск и обновление на сервере:

```bash
cd ~/Aliance-Generals && git pull && rm -rf dist && npm run build && pm2 restart generals-game
```

Что даёт своя база вместо облачной: транзакции, копии каждые 15 минут,
история состояния каждого игрока за 3 месяца, откат отдельной коллекции,
журнал действий на 90 дней в сжатых суточных блоках. Ничего из этого
в облачном режиме не было. Как этим пользоваться — `ВОССТАНОВЛЕНИЕ.md`
и `РУКОВОДСТВО-АДМИНА.md`.

> **Без `RESEND_API_KEY`** почта подтверждается автоматически (удобно для тестов).
> Для реальных писем — бесплатный ключ на [resend.com](https://resend.com) (3000 писем/мес).

## 🌐 Адреса игроков (если в панели у всех 127.0.0.1)

Игра стоит за nginx, и настоящий адрес игрока знает только он. Если
nginx не передаёт адрес дальше, сервер видит сам себя — у **всех**
игроков. Игра при этом работает нормально, поэтому проблему легко не
заметить: тихо ломаются журнал входов, поиск мультоводов и блокировка
по адресу.

**Диагностика — одной командой:**

```bash
cd ~/Aliance-Generals && bash tools/check-proxy.sh
```

Скрипт ничего не меняет: находит боевые конфиги, показывает, в каких
блоках не хватает заголовков, и печатает готовые строки.

**Починка.** В **каждый** блок `location`, который проксирует на игру:

```nginx
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

Затем:

```bash
sudo nginx -t && sudo nginx -s reload
```

Проверить результат: **панель → «Техника» → «Проверки» → «Проверка
сети»**. В строке «Определён адрес» должен появиться внешний адрес, а
`x-real-ip` перестанет быть `(нет)`.

Адреса записываются **при входе**, поэтому у тех, кто зашёл раньше,
останется старая запись, пока они не зайдут снова. Это не ошибка:
задним числом мы не знаем, откуда они заходили, и выдумывать не стоит.

Пока адреса не передаются, панель честно говорит, что проверка на
мультоводов слепа, и не показывает ложных совпадений. Сервер,
работающий с `NODE_ENV=production`, дополнительно пишет об этом в лог
один раз после первых 50 запросов.

## ✉️ Письма игрокам

Подтверждение почты при регистрации, восстановление пароля и новостная
рассылка. Отправляет Unisender Go (российский — письма реже уходят в спам
у mail.ru и Яндекса); Resend оставлен запасным.

```ini
UNISENDER_API_KEY=ключ из панели Unisender Go
EMAIL_FROM=Генералы <noreply@ваш-домен>
APP_URL=https://ваш-домен
```

Тексты писем правятся в панели: **«Письма»** — тема, разметка,
подстановки `{{имя}}`, `{{ссылка}}`, `{{игра}}`, `{{сайт}}`. Там же
рассылка по игрокам с подтверждённой почтой и её прогресс.

Пока ключ не задан, почта у новых игроков подтверждается сама — иначе
никто не смог бы войти. Полная настройка с нуля, включая DNS-записи
домена, — `ПОЧТА-И-ДОМЕН.md`.

## 🚪 Слежка за входами

**Панель → «Игроки» → карточка → «Входы и устройства»**: адрес и
устройство регистрации, все устройства аккаунта с адресами по каждому,
открытые прямо сейчас входы, журнал безопасности (смена пароля, новое
устройство, 2FA, выброс из кабинета).

**Панель → «Открытые входы»**: кто сейчас в игре и с чего, кнопки
закрыть одну сессию, все сессии игрока или все сразу.

Устройство узнаётся по строке браузера **и** отпечатку (экран, часовой
пояс, язык, число ядер) — без него половина игроков выглядела одинаково.
Подробности и оговорки — `АДРЕСА-И-ВЫБРОС.md`.

## 🔑 Администратор

**Права выдаются только на сервере** — через сайт, регистрацию или API
их получить нельзя. Раньше первый зарегистрировавшийся становился
администратором; это убрано намеренно.

```bash
node tools/grant-admin.js "Позывной" --owner   # владелец (все права)
node tools/grant-admin.js "Позывной"           # администратор
node tools/grant-admin.js --list               # кто уже назначен
```

Сервер при этом должен быть остановлен: он держит базу в памяти и
перезапишет её при выходе.

`/admin` позволяет:
- Искать игроков и выдавать ресурсы
- Управлять скидками по разделам
- Смотреть **журнал всех действий** игроков (покупки, бои, прокачки)

│   │   └── utils.ts       # ApiError, uid, hashPassword

│   └── routes.ts          # карта API-маршрутов

## 🧪 Автотесты

```bash
npm run build
node test/smoke.js          # сквозной тест: поднимает сервер себе сам
for f in test/*.js; do node "$f" || echo "УПАЛ: $f"; done   # весь набор
```

`smoke.js` проходит игру целиком через HTTP (регистрация, бои, миссии,
рынок, клуб, альянс, почта, админка) — сервер и временную базу он
создаёт и убирает сам, ничего запускать заранее не нужно.
