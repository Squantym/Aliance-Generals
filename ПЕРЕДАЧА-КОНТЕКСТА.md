### Что появилось в 190–194

**Окно обслуживания** (`src/services/maintenance.ts`)
Состояние живёт в базе, а не в памяти процесса, — иначе оно не пережило бы
тот самый перезапуск, ради которого включается. Поля:
`{ on, startAt, reason, until, auto, by, at, offAt, frozenFrom, lastFreeze }`.
Есть отложенный запуск (`startAt`), длительность и **самоснятие по сроку
только при явно поставленной галочке** `auto`. Текст владельца — многострочный.
Окно отдельное, не всплывающее, закрыть его игрок не может; после выхода
обновления закрывается само. Внутри — карусель из семи сжатых картинок
(`public/img/maintenance/1..7.webp`, 1200 px, WEBP q72), меняются каждые 7 с.

**Заморозка сроков** (`src/services/timefreeze.ts`)
Бои легиона и прочие таймеры сдвигаются вперёд на время простоя.
Правило: сдвигаем то, что игрок **пропустил бы** (бои, ракеты, баны), и
никогда — якоря начисления (`lastIncomeAt`, `earsLostAt`, `lastAttackAt`),
иначе обновление превращается в наказание. Защиты: ключ оканчивается на
`At|Until|Till`, не входит в список прошедшего, не начинается с `last`/`prev`,
значение в диапазоне `[1.4e12, 4e12]` и больше начала заморозки. Потолок — 12 часов.

**Раздельные тики** (`src/services/worldTick.ts`)
`gameTick()` замирает на обслуживании, `houseTick()` работает всегда, у
каждого **свой** try/catch.

**Обнуление мира** (`src/services/worldReset.ts` + `public/js/admin2/wipe.js`)
Кнопка только у владельца, требует ввода фразы `обнулить мир N`.
Порядок: включить обслуживание → снять замороженный снимок базы в
`data/worlds/` → собрать архивную запись → **запомнить то, что переживёт** →
стереть всё → вернуть запомненное → записать в журнал. Нет снимка или он
меньше 4096 байт — отказ.

**Обязательное подтверждение почты** (`src/services/email.ts`)
Был тихий режим разработчика: `autoVerified = !email.isConfigured`, из-за
него на боевом сервере регистрация пускала в игру без письма. Теперь нужен
явный `ALLOW_UNVERIFIED_EMAIL=1` (или `TEST_WORLD=1`, или `NODE_ENV=test`),
иначе регистрация просто закрыта с внятной причиной.

**Чтение `.env`** (`server.ts`)
Пустая переменная окружения больше не побеждает значение из файла. На старте
печатается, какие строки проигнорированы и какие пусты.

**Состояние регистрации в API**
`/api/world` отдаёт `registration: { open, why }` — причина в порядке:
обслуживание, тестовый мир, почта. Вкладка «Регистрация» не рисуется вовсе,
если закрыта; вместо неё карточка с причиной.

**2FA**
Панель врала: после успешного включения заголовок оставался «НЕ ЗАВЕРШЁН».
Теперь полная перерисовка, коды восстановления показываются с кнопкой
«Я сохранил коды».

**`tools/diag.js`** — печатает разом всё, что раньше выяснялось десятью
вопросами. Секретов не печатает, только имена и длины.

## Не доделано

### Срочное

1. **Выкатить 194** на `~/Aliance-Generals` и `~/Aliance-Generals-test`.
2. **Висит окно обслуживания** над работающей игрой, владелец его не включал.
   Неизвестный факт — сырая строка `maintenance` в боевой базе. Её покажет
   `node tools/diag.js`. Аварийно снимается `node tools/diag.js --open`.
3. **`SMTPBZ_API_KEY` не подхватывается** — на каждой живой проверке
   `mailConfigured: false`. Строка в `.env` не проверена глазами; `diag.js`
   покажет, есть ли она, не пуста ли и нет ли дубля.

### Хвосты

4. Перенести снимок первого обнуления из ротации:
   `cp data/backups/generals-wipe-2026-08-30T18-45-06-776.db data/worlds/mir-01-2026-08-30.db`
   (в `data/backups/` ротация по количеству — снимок затрётся).
5. Удалить в DNS запись `gokey._domainkey` — это живой DKIM-ключ Unisender Go,
   а Unisender из игры вырезан. MX-записей нет, поэтому `postmaster@` не может
   принимать отчёты DMARC.
6. Боевой nginx: `proxy_pass http://localhost:3000` → `http://127.0.0.1:3000`
   (иначе резолв в `::1` при живом IPv6).
7. Заполнить объект `LEGAL` в `public/js/legal.js`.
8. Уведомление в РКН; три почтовых ящика (обращения, платежи, общий).

### Доступ по SSH для Claude

Заводится пользователь `claude` с ключом `~/.ssh/generals_claude`, права
только на чтение через `setfacl`, `.env` закрыт наглухо (`setfacl -x` + 600).
Проверка настроена правильно, если под `claude` читается `package.json`, но
`cat .env` и `touch` дают Permission denied.

**Из облачной сессии SSH невозможен** — порт 22 закрыт, ssh-клиента нет
(проверено). Работать по SSH можно только из сессии Code, запущенной
на компьютере владельца.
