# Обновления и тестовый мир

Как выкатывать правки, не ломая игру живым игрокам, и где их проверять
до выката.

---

## Часть 1. Экран обновления

### Что он делает

Пока режим включён, обычный игрок в игру не попадает: вместо неё
**отдельный экран** «Идёт обновление» — не всплывающее окно поверх игры,
а полноэкранная страница. Игра под ним спрятана: показывать интерфейс,
который ни на что не отвечает, значит приглашать по нему кликать.

Закрыть его нельзя: ни крестика, ни кнопки, ни клика мимо. Он **уходит
сам**, как только игру откроют, — перезагрузкой страницы: за время
обновления поменялись и код, и разметка, так что «просто спрятать окно»
оставило бы человека на старой версии. Проверяет он себя раз в двадцать
секунд.

В окне: ваш текст (любой длины, в несколько абзацев), ориентировочный
остаток и **карусель картинок** — семь кадров, сменяются каждые семь
секунд. Ширина средняя, около 620 пикселей: на широком мониторе строка
во весь экран нечитаема.

**Сотрудники проходят как обычно.** Иначе снять режим было бы нечем:
панель — тоже часть игры.

### Заморозка боёв и таймеров

Пока игра закрыта, **мир не движется**: бои легиона не стартуют, ракеты
не долетают, аукционы не разрешаются, спуски в шахту не финализируются.

В момент открытия все назначенные сроки сдвигаются вперёд ровно на
длительность простоя. Было «бой через 5 минут», закрыли на 30 — после
открытия снова «бой через 5 минут».

Без этого было бы два одинаково плохих исхода: бой прошёл бы в закрытой
игре (все участники проиграли бы, не сделав ни одного хода), либо
начался бы через десять секунд после открытия — раньше, чем люди успеют
вернуться.

**Что НЕ замораживается — и это намеренно.** Доход, регенерация, лечение
в госпитале, отрастание уха идут своим ходом. Замораживается то, что
игрок **пропустил бы**; то, что копится **в его пользу** без него, не
трогаем. Иначе обновление превращалось бы в наказание: и из игры
выгнали, и полчаса лечения не засчитали.

Предел — двенадцать часов. Окно, забытое включённым на трое суток, не
сдвинет сроки на трое суток вперёд: это была бы уже не заморозка, а
порча базы. В таком случае в журнал пишется предупреждение, и сроки
остаются как есть.

Панель показывает, что заморозка работает («игровые таймеры стоят
с 14:20») и что дала последняя разморозка («переехало 143 значения»).

### Как включить

**Панель → «Обновление».** Три поля и две кнопки:

| Поле | Что значит |
|---|---|
| Текст для игроков | многострочный: что чините, надолго ли, что с прогрессом |
| Начать через … мин | 0 — закрыть сейчас; 120 — назначить на через два часа |
| Длительность … мин | ориентировочный срок, считается **от начала окна** |
| ☐ открыть игру самому по истечении срока | по умолчанию снята |

**«Закрыть игру сейчас»** — как раньше: игра закрывается немедленно, поле
задержки игнорируется (набрали 480, промахнулись кнопкой — игра всё
равно закроется сейчас, а не через восемь часов).

**«Назначить на потом»** — окно назначается, но **игра продолжает
работать**. Игроки видят сверху полосу «через 40 мин игра закроется на
обновление» с обратным отсчётом; когда время придёт, полоса сама
сменится закрывающим экраном. До начала можно всё отменить одной
кнопкой.

### Про галочку самооткрытия

Срок — прежде всего надпись для игрока. Без галочки режим по времени
**не снимается**: если обновление затянулось, автоматически открытые
двери впустили бы людей в сломанную игру. Открывает человек, глазами
убедившись.

Галочка нужна ровно для одного случая: заранее назначенная профилактика
(«в 04:00, на полчаса»), которую вы не собираетесь закрывать вручную в
полпятого утра. Тогда игра откроется сама по истечении срока.

**Выкат кнопкой галочку не ставит никогда.** После обновления игра может
не подняться, и о поломке вам должны сообщить не игроки.

Если срок не назван (длительность 0), галочка молча не срабатывает:
открывать было бы не по чему, а окно, которое «должно было открыться
само», но не открылось, — худший из вариантов.

### Что закрывается, а что нет

| | |
|---|---|
| Игровые запросы обычных игроков | 503 с вашей причиной |
| `/api/me` игрока | 200 с причиной — чтобы клиент показал окно, а не ошибку |
| Регистрация новых | закрыта: человек попал бы в игру, которая через минуту перезапустится |
| Сотрудники, панель | работают как обычно |
| Статические файлы, документы | открыты |

Пока окно только **назначено** и ещё не наступило, не закрывается
ничего: игра работает, регистрация открыта, игроки играют. Иначе
«назначить профилактику на ночь» означало бы «выключить игру прямо
сейчас», и узнали бы вы об этом от игроков.

### Честная оговорка про секунды самого перезапуска

Экран рисует сервер игры. Пока процесс перезагружается — это секунд
десять–тридцать — отвечать некому, и вместо окна браузер покажет ошибку
nginx.

Закрыть и эти секунды может только сам nginx. Настраивается один раз:

```nginx
# /etc/nginx/sites-available/aliance-general.ru

server {
    server_name aliance-general.ru;

    root /var/www/maintenance;          # сюда положить maintenance.html

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Игра не отвечает — значит идёт перезапуск. Показываем свою
        # страницу вместо «502 Bad Gateway».
        proxy_intercept_errors on;
        error_page 502 503 504 = @maintenance;
    }

    location @maintenance {
        root /var/www/maintenance;
        try_files /maintenance.html =503;
        internal;
    }
}
```

Страницу возьмите из `public/maintenance.html` в этом репозитории:

```bash
sudo mkdir -p /var/www/maintenance
sudo cp ~/Aliance-Generals/public/maintenance.html /var/www/maintenance/
sudo nginx -t && sudo systemctl reload nginx
```

Она сама перепроверяет сервер каждые десять секунд и перезагружает
страницу, когда игра поднимется.

## Часть 2. Тестовый мир

### Как он устроен

Тестовый мир — **отдельная установка игры на том же сервере**: свой
процесс pm2, свой порт, своя папка данных, свой поддомен.

Не «вторая половина» внутри одной игры. Разделять миры внутри одной базы
означало бы протащить условие «мир такой-то» через каждый запрос,
рейтинг, бой, альянс и рассылку — сотни мест. Одно забытое место, и
тестовый игрок бьёт боевого либо попадает в общий рейтинг, причём
заметить это можно спустя недели. У отдельных процессов разные файлы
базы: они физически не видят друг друга, и забывать тут нечего.

| | Боевой | Тестовый |
|---|---|---|
| Папка | `~/Aliance-Generals` | `~/Aliance-Generals-test` |
| Процесс pm2 | `generals-game` | `generals-test` |
| Порт | 3000 | 3001 |
| Адрес | aliance-general.ru | test.aliance-general.ru |
| База | своя | своя, пустая |
| Почта | SMTP.BZ | **не настроена намеренно** |
| Регистрация | открытая | закрыта, аккаунты выдаёт владелец |

### Развернуть

```bash
cd ~/Aliance-Generals
bash tools/setup-test-world.sh
```

Скрипт клонирует репозиторий во вторую папку, пишет ей собственный `.env`
и поднимает процесс. **Боевые ключи не копируются намеренно:** тестовый
мир, шлющий настоящие письма настоящим людям и тратящий лимит боевого
тарифа, — это авария, а не тест.

Дальше три шага руками.

**1. Поддомен.** Запись A для `test.aliance-general.ru` на тот же адрес
сервера, и блок nginx:

```nginx
server {
    server_name test.aliance-general.ru;
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Сертификат — тем же `certbot`, что и для основного домена.

**2. Первый аккаунт.** В тестовом мире своя база: она пуста, прав нет ни
у кого, а публичная регистрация закрыта. Круг разрывается из консоли:

```bash
cd ~/Aliance-Generals-test
node tools/test-account.js "ВашПозывной" вашпароль123
node tools/grant-admin.js "ВашПозывной" --owner --yes
```

`tools/test-account.js` работает **только** при `TEST_WORLD=1` и на
боевом сервере отказывается запускаться: там это была бы регистрация без
подтверждения почты, то есть дыра.

**3. Тестировщики.** Панель тестового мира → «Обновление» → «Создать
аккаунт». Логин и пароль показываются **один раз** — передайте их
человеку. В базе пароль хранится только хешем, показать его повторно
неоткуда.

### Как выглядит тестовый мир

Сверху висит полосатая жёлто-коричневая полоса «🧪 Тестовый мир — это не
боевая игра». Всегда и поверх всего. Перепутать тестовое окно с боевым и
раздать награды не тем людям — ошибка, которая случается ровно один раз
и запоминается надолго.

### Обновить тестовый мир

Панель **тестового** мира → «Обновление» → **«Обновить тестовый мир»**.
Поле версии оставьте пустым — возьмётся последнее из вашей ветки.

Кнопка делает ровно то же, что команда в консоли, — консоль остаётся
запасным путём:

```bash
cd ~/Aliance-Generals-test && bash tools/deploy.sh origin/ваша-ветка
```

## Часть 3. Выкат на боевой

### Порядок работы

1. Пушите правку на GitHub — как обычно.
2. Панель **теста** → «Обновление» → «Обновить тестовый мир». Код с
   GitHub забирает эта кнопка. **На боевой сервер он при этом не
   попадает** — там ничего не происходит, пока вы сами не нажмёте выкат.
3. Проверяете вместе с тестировщиками.
4. В панели **тестового** мира, раздел «Обновление», копируете номер
   версии — он показан целиком, по клику выделяется.
5. *По желанию:* заранее предупреждаете игроков. Панель **боевого**
   мира → «начать через 60 мин», длительность 20 → «Назначить на потом».
   Игра работает, игроки видят обратный отсчёт и успевают доиграть.
6. В панели **боевого** мира: «Обновление» → вставляете номер →
   «Выкатить».
7. Игра закрывается сама. Идёт сборка и перезапуск — несколько минут.
8. Проверяете боевой сервер своими глазами.
9. Жмёте **«Открыть игру для игроков»**.

**Про `git pull` на сервере.** Он больше не нужен ни для теста, ни для
боевого: обе кнопки делают это сами, каждая в своей папке. Если по
привычке сделать `git pull` в `~/Aliance-Generals`, ничего страшного не
случится и ничего не изменится — процесс продолжит работать со старой
сборкой из `dist/`, пока не будет пересборки и перезапуска. Опасно
другое: `git pull` **без** `npm run build` перед `pm2 restart` — тогда
поднимется старый `dist/` поверх нового кода. Кнопка делает всё в
правильном порядке и сборку ставит **до** перезапуска.

Шаг 8 отдельный намеренно: после обновления игра может не подняться —
ошибка сборки, забытая переменная окружения, несовместимая правка.
Автоматически открытые двери означали бы, что о поломке вам сообщат
игроки.

### Что делает кнопка

Запускает `tools/deploy.sh` с указанным номером версии. Скрипт:

1. делает страховочную копию базы;
2. забирает код и переключается на нужную версию;
3. ставит зависимости и **собирает** — если сборка упала, игра
   продолжает работать на старой версии, потому что процесс ещё не
   трогали;
4. перезапускает pm2 и ждёт ответа сервера до минуты;
5. печатает номер прежней версии — это точка отката.

### Откат

Номер прежней версии виден в панели («Точка отката») и в журнале выката.
Вставляете его в то же поле и жмёте «Выкатить». Либо руками:

```bash
cd ~/Aliance-Generals && bash tools/deploy.sh 9f3c1a2b
```

### Почему кнопка не опасна

Кнопка, запускающая обновление на сервере, — это по сути удалённое
выполнение кода. Поэтому:

- запускается **фиксированный скрипт** из репозитория; панель передаёт
  ему только номер версии, а не команду;
- номер **проверяется по образцу** дважды — в панели и в самом скрипте.
  Разрешены только 7–40 шестнадцатеричных знаков либо `origin/ветка`.
  Строка вида `origin/main; rm -rf /` отвергается до запуска оболочки;
- доступ только у **владельца**, и только со включённым вторым
  фактором — вход в панель без него закрыт;
- каждый выкат пишется в журнал: кто, когда, какую версию.

Проверяется это не чтением кода, а тестом: `test/release.test.js`
скармливает выкату пять разных попыток инъекции и ждёт отказа по каждой.

## Быстрая шпаргалка

| Задача | Где |
|---|---|
| Закрыть игру на обновление | Панель → Обновление → «Закрыть игру сейчас» |
| Назначить окно на потом | Панель → Обновление → «начать через N мин» → «Назначить на потом» |
| Отменить назначенное | Панель → Обновление → «Отменить назначенное окно» |
| Открыть обратно | Панель → Обновление → «Открыть игру для игроков» |
| Завести тестировщика | Панель **тестового** мира → Обновление → «Создать аккаунт» |
| Обновить тестовый мир | Панель **теста** → Обновление → «Обновить тестовый мир» |
| Выкатить на боевой | Панель боевого → Обновление → номер версии → «Выкатить» |
| Откатиться | Тот же выкат, но с номером прежней версии |
| Выкат руками | `cd ~/Aliance-Generals && bash tools/deploy.sh <версия>` |
| Логи выката | Панель → Обновление → «Журнал выката», либо `data/deploy.log` |
